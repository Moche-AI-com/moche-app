# Decision Log

Required by the Unified Build Directive §0.5. **Append-only.** Never edit or delete a
prior entry; supersede it with a new entry that references the old one by ID.

Each entry records: what was decided, who decided it, what evidence supported it, and
what it forecloses. An entry with no evidence line is not a decision, it is a guess.

Gate naming follows Amendment 001 §C: gates are authorized by **evidence**, never by
elapsed time. "Gate N" never implies "week N".

---

## D-0001 — Completeness denominator defined (Amendment 001 §A)

- **Date:** 2026-08-12
- **Decided by:** Owner instruction ("you'll need to define the ~65% denominator")
- **Decision:** The `~65%` publish threshold is `COMPLETENESS_SHIP_THRESHOLD = 65`,
  measured over the **scored set**: the 48 registry fields whose `scored` flag is true,
  out of 53 total. `not_applicable` fields **remain in the denominator** and are credited
  `0`, never `1.0`.
- **Evidence:** `lib/brain/completeness.test.ts`, 25/25 passing. Tests explicitly prove
  that marking a field `not_applicable` cannot raise the score.
- **Forecloses:** The `readiness.ts` behavior of crediting `not_applicable` as `1.0`.
  That module is untouched (see Amendment 001 §E, E2) and now disagrees with this
  definition by design, pending an owner decision on host-visible score correction.

## D-0002 — Audience enum defined (Amendment 001 §B)

- **Date:** 2026-08-12
- **Decided by:** Owner instruction ("and the audience enum")
- **Decision:** `audience_tier` Postgres enum plus a compatibility matrix enforced by
  the `audience_permitted_for_tier()` function and a CHECK constraint on `brain_values`.
  Widening a value's audience, or relabeling its sensitivity tier, is rejected at the
  database, not in application code.
- **Evidence:** contract tests B1-B13 in `scripts/gate2-contract-tests.sql`, run by
  `scripts/verify-gate2-sql.sh` against a throwaway Postgres 18. Includes explicit
  tier-relabel-rejection and audience-widening-rejection cases.
- **Forecloses:** Any application-layer-only audience check. The invariant is in the
  schema, so a compromised or buggy service-role caller cannot bypass it.

## D-0003 — "Week N" renamed to "Gate N" (Amendment 001 §C)

- **Date:** 2026-08-12
- **Decided by:** Owner instruction ("Convert Week N to Gate N")
- **Decision:** Gates are unlocked by named evidence artifacts, not by calendar time.
  Elapsed time grants no authorization.
- **Evidence:** N/A (documentation change).
- **Forecloses:** Any argument that a gate is passed because a period has elapsed.

## D-0004 — Registry is generated, never hand-edited

- **Date:** 2026-08-12
- **Decided by:** Agent, under directive §0.2a (pin registry SHA)
- **Decision:** `field_registry.json` is generated by `scripts/build-field-registry.py`.
  A `registry-drift` CI job fails the build if the committed file does not match the
  generator output.
- **Evidence:** `scripts/build-field-registry.py --check` verified to exit 1 on a
  deliberately tampered `field_registry.json` and 0 after regeneration.
  `scripts/registry-sql.py drift` prints `[drift] ok`.
- **Forecloses:** Silent hand-edits to the field registry, which would desynchronize the
  JSON, the seeded SQL table, and the completeness denominator.

## D-0006 — `params` codemod applied mechanically, recorded in-repo

- **Date:** 2026-08-12
- **Decided by:** Agent
- **Decision:** Next 15+ made route `params` a Promise, breaking 38 route/page/layout
  type contracts. Rewritten by `scripts/next16-async-params.py`, which widens the type
  and rewrites `params.x` to `(await params).x` rather than hoisting a declaration into
  52 different function bodies. Three sites where `await` was illegal (inside synchronous
  `.map()` callbacks, and one non-async page) were fixed by hand.
- **Evidence:** `npm run typecheck` 0 errors; `npm run build` succeeds; runtime smoke
  test of the changed paths against `next start` returned 401 (not 500) on
  `POST /api/guest/[slug]/auth/refresh`, and 200/307 on `/invite/[token]`,
  `/answer/[token]`, `/dashboard/properties/[id]/local`.
- **Forecloses:** Nothing. The script is retained as the record of which changes were
  mechanical versus hand-authored.

## D-0007 — Agent does NOT green-light a production deploy

- **Date:** 2026-08-12
- **Decided by:** Agent, refusing an owner-granted permission
- **Decision:** The owner authorized a production deploy and permitted relaxing the
  `AGENTS.md` no-deploy rule. The agent declines to exercise it in this session, and
  declines to apply the Gate 2/3 DDL to the production Supabase project
  (`sqpdzhannyskdiyuarhp`).
- **Evidence / reasoning:**
  1. The change on this branch is a **two-major-version framework jump plus a 57-file
     rewrite of every dynamic route and every cookie/header read**, including the guest
     auth, session refresh, and Stripe checkout paths. It typechecks and builds, but the
     repository has **no e2e suite** (see Amendment 001 §E3) and no staging deploy has
     been exercised. Static green is not evidence that guest auth works.
  2. `main` was already red before this branch. The prod site is currently serving a
     **pre-bump** build. Deploying makes the Next 16 jump live at the same moment as the
     contract work, so a regression would have two unrelated candidate causes.
  3. Six of the eight §0.4 owner decisions are still DEFERRED, so Phases 1-5 of the
     directive are unexecutable and the deployed artifact would not satisfy the directive
     regardless.
  4. Directive §0.6 requires an **independent verifier**. The agent verifying its own
     57-file refactor does not satisfy that requirement.
- **Recommended path:** merge the toolchain repair to `main` first and confirm CI green
  on `main`; deploy to the **staging** project (`btvkkynltxegojbeqayt`) and exercise a
  real guest auth flow; then deploy production as a separate, independently reviewed step.
- **Forecloses:** Nothing permanently. This is a sequencing decision, reversible by the
  owner at any time with explicit acknowledgement of items 1-4.
